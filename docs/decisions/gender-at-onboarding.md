# 성별을 온보딩에서 받는다

**결정** — `app_user` 의 유저 입력 컬럼(닉네임·성별·소속)을 모두 받는다.
성별은 온보딩 필수 항목이며, 서버(`complete_onboarding`)가 비어 있으면 거부한다.

**이유** — 성별은 받은 투표의 **힌트로 파는 정보**다. 구 서비스 실측 누진 요금
200→300→500→1000 의 두 번째 단계가 GENDER 였는데, 성별을 받지 않는 동안에는
팔 것이 없어 3단계로 줄여두었다. 없는 정보를 하트를 받고 팔 수는 없기 때문이다.
성별을 받으면 이 단계가 되살아나고, 수익 구조를 원 서비스와 같은 모양으로 시험할 수 있다.

**영향**
- 힌트를 4단계로 되돌렸다: **성별(200) → 초성(300) → 반(500) → 전체 공개(1000)**.
  (2026-07-30 순서 조정 — 성별을 먼저 연다. 초성은 후보를 몇 명으로 좁혀버려서
  먼저 팔면 그다음 단계를 살 이유가 약해진다. 요금은 그대로 두었다.)
- `my_vote_received` 뷰에 `voter_gender` 를 추가했다. 1단계를 산 뒤에만 나온다.
- 수집 항목이 늘었으므로 **개인정보처리방침에 성별을 명시**한다. "닉네임 + 성별 +
  학교 + 반" 조합은 개인 특정 가능성이 더 높아진다 — 소규모 클로즈드 테스트라는
  전제가 그만큼 더 중요해졌다.
- `gender` 컬럼은 nullable 로 둔다. NOT NULL 로 바꾸려면 성별을 받기 전에 만들어진
  기존 행을 먼저 채워야 하는데, 실제 사람의 성별을 임의로 지어낼 수는 없다.
  강제는 가입 함수에서 한다.
- 성별을 받기 전에 가입한 계정은 값이 비어 있다. 그 사람이 뽑은 투표에 GENDER 힌트를
  사면 빈 값이 나가므로, 클로즈드 테스트 전에 초기화하고 다시 가입받는다.
