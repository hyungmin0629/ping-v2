# 1회성 답장을 연다 — 차단 화면 없이

**결정** — 지목당한 사람이 자기를 뽑은 사람에게 **한 번만** 답장할 수 있다.
20하트, 30자. 힌트를 열었든 안 열었든 보낼 수 있다.

**이건 미뤄둔 결정을 앞당긴다.** [[design-spec]] 2.2 는 "지목한 사람에게
익명 메시지"를 **차단 화면이 생긴 뒤에** 열 기능으로 분류해 두었다.
차단은 여전히 없다.

**그래도 여는 이유** — 위험의 크기가 다르다. 30자에 한 번뿐이고, 무엇보다
**익명이 아니다.** 받는 쪽은 자기가 누구를 뽑았는지 알기 때문에 보낸 사람을
안다. 익명 메시지를 위험하다고 본 근거가 "사적인 메시지는 받은 사람이 말하기
전까지 아무도 모른다"였는데, 여기서는 대상이 처음부터 분명하다.

**대신 붙인 것** — 받은 답장을 신고할 수 있다(`report_reply`).
대상은 그 답장을 보낸 사람이고, 기존 `report` 의 USER 사유를 쓴다.
신고해도 자동으로 아무 일도 하지 않는다 — 자동 조치는 집단 신고에 취약해
진작에 기각한 방식이다. 기록만 남고 사람이 판단한다.

**대안**
- 차단 화면을 먼저 만든다. 기각하지 않고 **순서만 바꿨다.** 채팅방처럼
  주고받는 기능을 열 때는 차단이 먼저다 — 그때는 대화가 이어지므로
  "한 번 받고 끝"이 아니다.
- 답장도 익명으로. 기각. 익명이면 신고할 대상이 사라지고, 그게 바로
  익명 메시지를 미뤄둔 이유다.

**영향**
- `vote_received` 에 컬럼으로 붙였다(`reply_text`·`replied_at`). 답장은
  받은 투표 한 건에 **최대 하나**라 NULL 여부가 곧 그 제약이다.
  1:N 이 될 여지가 생기면 그때 테이블로 뽑는다.
- 하트 거래 유형에 `VOTE_REPLY` 를 추가했다. 원장은 `type_code` 로 의미를
  읽으므로 새 소비처는 등록해야 한다 — 구 스키마처럼 delta 값으로 의미를
  역추론하는 자리를 만들지 않는다.
- 하트 소비처가 힌트 하나에서 둘로 늘었다. 하트 경제 분석이 그만큼 넓어진다.

## 이어지는 결정
- [[report-first-block-later|신고는 게시판과 함께, 차단은 뒤로]]
  — 차단 화면 없이 1:1 텍스트를 열었다. **앞 결정이 미뤄둔 것을 뒤 결정이 앞당긴다**
- [[selectable-hints|힌트를 골라 사게 바꾼다 — 순차 4단계 폐기]]
  — 하트 소비처 둘. 답장이 두 번째로 생긴 소비처다
- [[voter-identity-view-only|투표자 신원은 뷰로만 노출한다]]
  — 지목당한 쪽이 뽑은 쪽에게 말을 건다 — 이건 익명이 아니다
