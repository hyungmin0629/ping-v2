# 중도 이탈 세션은 EXPIRED 로 적는다 — 완료율이 98.6%로 보이던 이유

**결정** — 문항을 다 받지 못하고 끝난 세션(`n_items < items_per_session`)의
`vote_session.status` 를 **`EXPIRED`** 로 적는다. `session_status` enum 에
이미 있는 값이라 **스키마는 건드리지 않는다.**

**이유** — 중도 이탈은 **이미 구현되어 있었다.** 문항 수가 실제로 줄어들고,
이탈의 60%가 1~3문항에 몰리는 것까지 설정대로 나왔다. 문제는 **기록**이었다.

옛 판정식이 이랬다 —

```
status = COMPLETED if completed >= n_items * 0.8 else IN_PROGRESS
```

`n_items` 는 **이미 이탈로 줄어든 수**다. 1문항만 받고 나간 세션은
"1개 중 1개 했으니 완료"가 되어 `COMPLETED` 로 찍혔다.

| 재는 방법 | v1 | v2 |
|---|---|---|
| `status = 'COMPLETED'` | **98.6%** | 85.0% |
| `item_count = 10` | 84.6% | 85.4% |
| **두 값의 차이** | **14.0%p** | **0.4%p** |

**같은 지표를 두 방법으로 재면 값이 전혀 달랐다.** 이런 데이터로는
퍼널 분석을 할 수 없다 — 어느 쪽을 믿어야 할지 정할 근거가 없기 때문이다.

**대안** — enum 에 `ABANDONED` 를 추가하는 안을 기각했다. `EXPIRED` 가
"끝까지 안 가고 끝난 세션"이라는 뜻을 이미 담고 있고, **스키마 변경은
실서비스 마이그레이션을 부른다.**

**영향**

- `COMPLETED` 85.0%(평균 10문항) · `EXPIRED` 14.6%(평균 3.8문항) ·
  `IN_PROGRESS` 0.4%.
- **퍼널 분석에 쓸 수 있게 됐다.**
- ✅ 정합성 17종과 충돌하지 않는다 — "선택 없는 완료 투표" 검사는
  `vote_item.voted_at` 을 볼 뿐 세션 상태를 보지 않는다.
- ⚠️ **실서비스 앱이 중도 이탈 세션을 어떤 상태로 남기는지는 따로 확인해야 한다.**
  생성기만 고쳤다.
