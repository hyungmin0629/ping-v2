# 페르소나는 분류가 아니라 생성 편의다

**결정** — 합성 유저에게 6개 페르소나(관망·투표·소셜·게시판·고관여·악성)를 주되,
**결과 데이터에 6덩어리가 또렷하게 남으면 실패로 본다.** 배정을 세 가지로 흐린다 —
혼합(25%) · 트레잇 교차(8%) · 무배정(4%). 트레잇마다 **따로** 개인 편차를 곱한다.

**이유** — 페르소나가 없던 시절에는 글쓰기·투표·힌트·결제가 전부 독립 추첨이라
"글도 쓰고 투표도 많이 하는 사람"이 우연으로만 생겼다. 상관분석이 전부
"활동량이 많으면 다 많다"로 수렴했다.

그런데 유형을 그대로 심으면 반대 문제가 생긴다. **분석자가 클러스터링해서 우리가
넣은 6개를 그대로 되찾는 데이터에는 발견할 것이 없다.** 작업자의 요구가 정확히
이것이었다 — "관망 페르소나이더라도 댓글을 많이 쓰는 유저가 있을 수 있게".

**대안** — 유형 없이 트레잇만 독립적으로 흔드는 안을 기각했다. 그러면 트레잇 사이
상관이 0 이라 "어떤 유형의 사람인가"라는 질문 자체가 성립하지 않는다.

**⚠️ 모집단 평균은 실측으로 정규화한다** — 트레잇 배수는 상대값이고, 유저를 다
만든 뒤 **실제 평균으로 나눈다.** 해석적으로 계산하지 않는 이유는 개인 편차의
분포가 무엇이든 정확히 보존되기 때문이다. 이걸 안 하면 `read_rate` 처럼 힘들게
맞춰 둔 값이 조용히 어긋난다(에러는 안 난다).

**⚠️ 확률에 배수를 걸면 평균이 샌다** — 1을 넘지 않게 오즈비로 변환하면 변환이
볼록해서 평균이 아래로 당겨진다. 실제로 열람률이 55.5% → 39.2% 로 샜다.
설정값을 손으로 올려 맞추면 트레잇 분포가 바뀔 때마다 다시 틀어지므로,
**보정 계수를 이분법으로 풀어 캐시**한다(`Generator.pchance`).

**영향**

- 유형 라벨은 `data/personas.json` 에 정답지로만 남기고 **DB·CSV 에 넣지 않는다.**
  저장하면 분석자가 정답을 보고 시작한다. 탐지 연습용 이상치를 봉인하는 것과 같은 이유다.
- 검증 기준이 "유형 간 차이가 보이는가"가 아니라 **"유형이 깔끔하게 안 갈리는가"** 다.
  각 행동 지표의 상위 10% 에 5개 이상 유형이 섞여 있어야 통과다.
- 악성형은 탐지 연습용 이상치(어뷰저·새벽 활동·반복 지목)와 **분리한다.** 전자는 신고를
  많이 받는 사람이고 후자는 행동 패턴이 이상한 사람이다. 겹치면 탐지가 시시해진다.
- 실측 결과는 `docs/EDA-sample-1m-v3.pdf` 2장.
