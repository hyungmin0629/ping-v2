# 워터마크를 스냅샷보다 5분 뒤로 물려 저장한다

**결정** — 증분 적재를 마친 뒤 워터마크를 `스냅샷 시각 - 5분` 으로 기록한다.
매 실행이 최근 5분치를 다시 읽는다.

**이유** — 워터마크 경합 때문이다. `updated_at` 은 트리거가 `now()` 로 채우는데,
Postgres 의 `now()` 는 **트랜잭션이 시작한 시각**이다.

쓰기 트랜잭션 W 가 09:00:00 에 시작해 `updated_at = 09:00:00` 을 박고
09:00:02 에 커밋한다고 하자. 적재가 09:00:01 에 스냅샷을 뜨면 W 는 아직 커밋
전이라 **보이지 않는다.** 그런데 워터마크는 09:00:01 로 전진한다. 다음 적재는
`updated_at > 09:00:01` 을 뜨므로 W 의 행은 **영원히 걸리지 않는다.**

확률은 낮다(이 앱의 쓰기는 RPC 하나, 밀리초 단위다). 그러나 이런 누락은
오류를 내지 않는다 — 쿼리는 멀쩡히 답을 주고, 그 답이 틀렸다는 걸 알 방법이 없다.
`verify_load.py` 가 행 수로 잡아주긴 하지만, **갱신 누락은 행 수로도 안 잡힌다.**

**대안**
- 트랜잭션 ID(`pg_current_snapshot`)로 추적한다. 정확하지만 원천마다 상태를
  더 들고 다녀야 하고, 이 규모에서 얻는 게 없다.
- 무시한다. 기각. 5분 재읽기의 값이 훨씬 싸다 — MERGE 는 멱등이라
  같은 행을 몇 번 읽어도 결과가 같고, 5분치는 실유저 몇 행 수준이다.

**영향** — 매 실행이 최근 5분치를 다시 읽는다. 합성 786만 행처럼 한 번 만들고
안 바뀌는 원천에서는 재읽기가 0 이다.
