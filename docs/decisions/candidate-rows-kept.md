# 후보 4명을 행으로 저장하고 셔플 전후를 모두 남긴다

**결정** — `vote_candidate`에 `shuffle_round` 컬럼을 두어 최초 후보(0)와 셔플 후 후보(1)를 모두 보존.

**이유** — 기존엔 세트↔피스 관계가 `longtext` JSON 배열이라 SQL로 펼칠 수 없었다.
또 "어떤 후보였을 때 셔플을 눌렀는가"는 광고 수익과 직결되는 분석인데 데이터가 없으면 못 본다.

**영향** — 셔플 유발 요인 분석이 가능해진다. 대신 후보 행 수가 최대 2배가 된다.
