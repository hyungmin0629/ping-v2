# NEIS 가 하루씩 주는 것을 기간으로 묶는다

**결정** — NEIS 학사일정은 **날짜마다 한 행**으로 온다. 이어지는 날짜를
하나로 합쳐 `start_date`~`end_date` 로 저장한다. 사이에 낀 주말은 이어진
것으로 본다.

**이유** — 여름방학이 7월 20일~8월 17일이면 NEIS 는 **29개 행**을 준다.
그대로 넣으면 달력이 방학으로 도배되고 목록에도 같은 이름이 29번 나온다.
`school_event` 가 시작일과 종료일을 따로 가진 것이 애초에 이걸 하라는 뜻이다.

주말을 건너뛰는 것은 학교가 토·일에 일정을 안 넣는 경우가 많아서다.
끊긴 것으로 보면 "1학기 기말고사"가 주 단위로 쪼개진다. 실제로 서울고의
기말고사가 6월 30일~7월 6일로 주말을 건너 이어졌다.

**다시 받을 때는 지우고 넣는다.** 묶이는 범위가 바뀔 수 있어서(뒤에 하루가
더 붙는 등) `ON CONFLICT` 로는 옛 조각이 남는다. 사람이 손댄 행
(`is_manually_overridden`)은 지우지 않는다.

**영향 — 종류를 우리가 추측한다.** NEIS 는 일정 **종류를 주지 않는다.**
이름과 휴업일 여부만 준다. `event_type` 은 제목의 낱말로 정한다
(방학·휴업 → HOLIDAY, 고사·평가 → EXAM …). 못 알아보면 ETC 다.

서울고 139건 중 **87건이 ETC** 다. 낱말 목록을 늘려 줄일 수는 있지만
학교마다 이름이 제각각이라 끝이 없다. 화면이 종류를 점 색으로만 쓰고
제목을 그대로 보여주므로, 틀리게 분류하는 것보다 ETC 가 낫다.

⚠️ **분석에서 `event_type` 을 근거로 쓸 때는 이 사실을 기억할 것.**
"시험 기간의 투표량"을 볼 때 EXAM 만 세면 놓치는 것이 있다.

**첫 시도가 조용히 틀렸다** — NEIS 는 휴업일이 아닌 날에 빈 값이 아니라
**"해당없음"이라는 문자열**을 넣는다. 빈 값과 `-` 만 걸렀더니 299건이 전부
HOLIDAY 로 들어갔다. 오류는 나지 않았고 적재도 "성공"했다. 종류별 집계를
찍어보지 않았으면 못 봤다 — **수집기는 넣은 결과를 갈래별로 세어 출력한다.**
