# 후보가 4명이 안 되면 스코프를 낮추고, 그래도 안 되면 질문을 내지 않는다

> ⛔ **대체된 결정이다.** → [[pad-candidates-keep-scope]]

**결정** — 출제할 때 후보를 세어 4명이 안 되면 `CLASS → SCHOOL → GLOBAL` 로 한 단계씩
낮춘다. GLOBAL 에서도 모자라면 **그 질문은 출제하지 않는다**(세션에 넣지 않는다).
실제로 쓴 스코프는 `vote_item.candidate_scope` 에 남긴다.

**이유** — 친구 5명 게이트는 GLOBAL 후보만 보장한다. 친구가 5명이어도 같은 반 친구가
2명뿐이면 CLASS 질문을 낼 수 없다. 후보를 3명만 보여주거나 모르는 사람으로 채우는 것은
둘 다 나쁘다 — 전자는 선택지를 왜곡하고, 후자는 "세 스코프 모두 친구가 전제"라는
설계를 깬다.

**대안** — 후보 풀이 부족한 질문을 아예 질문 목록에서 빼기. 기각. 친구 구성은
사람마다 다르고 계속 바뀌므로, 질문 쪽이 아니라 출제 시점에 판단해야 한다.

**영향**
- 스코프를 낮춘 사실이 데이터에 남는다. `question.scope <> vote_item.candidate_scope`
  인 비율을 세면 "친구 구성이 얼마나 편중돼 있나"를 관찰할 수 있다.
- 질문을 건너뛰므로 세션의 문항 수가 10개보다 적을 수 있다. `vote_session.item_count`
  는 실제로 만든 수를 담는다.
- 유저에게 보이는 "건너뜀"은 없다. 애초에 그 질문이 나오지 않을 뿐이다
  (`vote_item` 에 스킵 컬럼이 없는 것과 같은 맥락이다).
