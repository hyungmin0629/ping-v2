# BigQuery 에 GCS 를 경유하지 않고 직접 올린다

**결정** — 추출한 행을 GCS 버킷에 내려놓지 않고 JSON 으로 곧장 올린다
(`load_table_from_json`). `GCS_BUCKET` 은 비워 둔다.

**이유** — GCS 경유는 대용량 적재의 정석이지만, 버킷·권한·수명주기 설정이
늘어나는 값을 이 규모가 정당화하지 못한다. raw 전체가 **450MB** 다.
`google-cloud-storage` 와 `pyarrow` 를 requirements 에서 뺐다.

**대안** — GCS 를 거치는 표준 경로. 기각. 데이터가 수십 GB 로 커지면
그때 다시 본다. 지금은 중간 저장소가 시간을 줄여주지 않는다.

**영향**
- 적재는 배치(5만 행)로 나눠 올린다. 786만 행을 한 덩어리로 만들면 메모리가 터진다.
- 서비스 계정 키(`credentials.json`)는 커밋하지 않는다. Airflow 컨테이너에는
  프로젝트 폴더 마운트로 들어간다 — 그래서 이 컴포즈는 로컬 전용이다.

**정정 (2026-07-30)** — 처음에는 "결제 계정 없이 샌드박스로 시작한다"고 적었으나
사실이 아니었다. 데이터셋과 테이블의 만료 설정을 조회하니 전부 비어 있었다.
샌드박스라면 데이터셋 생성 시 **60일 만료가 강제로** 걸리므로, 첫 적재 시점에
이미 결제 계정이 붙어 있었다는 뜻이다. 60일 만료 제약은 없다.
대신 무료 한도(저장 10GiB · 쿼리 1TiB/월)를 넘으면 막히지 않고 과금되므로
예산 알림을 걸어 둔다.
