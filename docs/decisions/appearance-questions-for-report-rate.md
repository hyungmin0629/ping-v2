# 외모·신체 질문을 연다 — 민감 질문이 없으면 신고율을 못 잰다

**결정** — `question_category.APPEARANCE` 를 `is_active = true` 로 켠다
(migration 012). 합성 데이터에서 전체 질문의 6% 를 외모·스타일 질문으로 만든다.

⚠️ **실서비스에 반영되는 변경이다.** 이 마이그레이션이 Supabase 에 적용되면
외모 질문이 실제 이용자에게 출제될 수 있게 된다.

**이유** — `is_sensitive` 플래그는 처음부터 스키마에 있었지만 **민감한 질문이
하나도 없어서 아무것도 구분하지 못했다.** 실제로 얼마나 신고되는지 모르면
그 플래그도, 신고 파이프라인도 검증할 수 없다. 신고 사유에 이미
`Q_APPEARANCE`('외모 비하 소지')가 있는데 쓰일 일이 없었다.

**대안** — 비활성 카테고리에 질문만 만드는 안을 기각했다. 실서비스에는 영향이
없지만 "비활성인데 질문이 있다"는 어긋남이 데이터에 남고, 그 상태를 분석자가
어떻게 읽어야 할지 정의할 수 없다.

**⚠️ 무엇을 넣지 않는가** — **칭찬 방향만** 쓴다. 스타일·분위기·첫인상·목소리.
비하로 읽힐 문장은 넣지 않는다. 이 결정은 "외모 평가를 연다"가 아니라
"민감 카테고리를 측정 가능하게 만든다"이다.

**영향**

- **뒤집는 대상에 결정 노드가 없었다.** "외모·신체 관련 질문 제외"는 [[CLAUDE]] 의
  '확정된 제약'에만 있었고 `docs/decisions/` 에는 기록이 없다. 그래서 `superseded`
  를 달 파일이 없고, CLAUDE.md 를 직접 고쳤다.
  ⚠️ **제약을 규약 파일에만 적으면 뒤집을 때 이력이 안 남는다**는 사례다.
- 90_seed_master.sql 은 `ON CONFLICT DO NOTHING` 이라 기존 DB 에 안 먹는다.
  **시드(새 DB용)와 마이그레이션(기존 DB용)을 둘 다 고쳐야 한다.** 한쪽만 고치면
  로컬과 Supabase 가 갈라지고, `replay_check` 가 그제서야 잡는다.
- 실측: 240개 중 15개(6.3%)가 외모 질문이고 그중 4건이 신고됐다.
