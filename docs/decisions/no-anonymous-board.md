# 익명 게시판을 v1에서 제외

**결정** — 스키마에는 설계해두되 v1 서비스에서는 열지 않는다.

**이유** — 익명 게시판은 모니터링 인력이 필수다. 기존 서비스에서 신고 시스템이 사실상 작동하지 않았던
전례가 있고, 1인 프로젝트로는 신고 검토를 감당할 수 없다. 사고가 났을 때 책임을 질 수 없는 기능은 열지 않는다.

**대안** — 열되 신고를 자동 숨김 처리. 기각. 자동 숨김은 악용(집단 신고)에 취약하다.

**재검토 조건** (2026-07-29 추가) — 아래 둘이 **동시에** 충족될 때만 다시 본다.
신고 검토를 실제로 맡을 사람이 있을 것, 그리고 이용자가 성인으로 유지될 것.
하나라도 빠지면 열지 않는다. 스키마(`post`, `post_comment`, `post_like`, `comment_like`)는
지우지 않고 그대로 둔다 — 판단이 바뀌는 것은 인력 문제이지 설계 문제가 아니기 때문이다.

**방향** (2026-07-29 작업자 확인) — **언젠가는 연다.** 다만 익명 그대로가 아니라
**자유게시판**(글쓴이의 닉네임이 드러나는) 형태로 바꿔서라도 연다.
글에 작성자가 붙으면 모니터링 부담이 크게 준다 — 익명 게시판을 막았던 이유가
"사고가 나도 책임을 물을 수 없다"였는데, 그 전제가 바뀌기 때문이다.

스키마는 이미 그렇게 되어 있다. `post.author_id` 는 NOT NULL 이고
(60_board.sql 주석: *"화면에는 익명으로 표시하되 author_id 는 내부에 남긴다"*),
익명 표시 여부는 **화면의 선택**이다. 자유게시판으로 열 때 DDL 변경은 필요 없다.
