# 두 원천의 id 가 겹친다 — 조인에 `_source` 를 강제한다

**결정** — 당장은 규칙으로 못 박고(`WHERE`·`JOIN` 에 `_source` 필수),
P6 stg 층에서 대리키를 만들어 구조적으로 막는다.

**이유** — 실측했더니 `app_user` 는 16개, `vote_item` 은 26개 id 가 두 원천에
동시에 존재한다. 적재는 키가 `(_source, id)` 라 안전하지만, **분석 쿼리는
아무도 지켜주지 않는다.** `JOIN ... USING(id)` 한 줄이면 실유저의 투표에
합성 유저의 프로필이 붙고, 그래도 오류는 나지 않는다.

**대안** — 원천별로 테이블을 나눈다. 기각. 분석 쿼리가 전부 두 벌이 되고,
"합성으로 검증한 쿼리를 실데이터에 그대로 돌린다"는 전제가 깨진다.

**영향** — P6 의 첫 작업은 stg 층에서 `_source || '-' || id` 형태의 대리키를
만드는 것이다. raw 를 직접 조인하는 쿼리는 임시로만 쓴다.
