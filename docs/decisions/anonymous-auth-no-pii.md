# 개인정보를 일절 받지 않는 익명 인증

**결정** — 이메일·전화번호·실명·비밀번호를 받지 않는다.
Supabase Anonymous Sign-in으로 접속 즉시 계정이 생기고, 유저가 입력하는 것은
**닉네임과 소속(학교·반)뿐**이다. 친구는 **초대 코드**를 주고받아 맺는다.

**이유** — MVP 단계에서 개인정보를 받으면 수집·보관·파기 의무가 생기고,
유출 시 책임이 따른다. 받지 않으면 그 위험 자체가 사라진다.
로그인 절차가 없어 진입 장벽도 낮아진다.

**대안** — 이메일 매직링크. 기각. 이메일은 개인정보이고, 메일함을 오가는 절차가
지인 대상 가벼운 테스트에는 과하다.

**영향**
- `app_user.phone_hash` 제거, `name_masked` → `nickname`, `invite_code` 추가
- `user_contact`(전화번호 해시)는 MVP DDL에서 생성하지 않는다
- `friend_recommendation.reason = MUTUAL_CONTACT`는 MVP에서 사용하지 않는다
- **알려진 한계**: 익명 계정은 브라우저에 귀속되어 캐시를 지우면 사라진다.
  MVP에서는 감수하고 안내 문구로 알린다. 복구 코드는 v2.
- ⚠️ "닉네임 + 학교 + 반"은 소규모 집단에서 개인 특정이 가능하므로,
  법적으로 비개인정보라고 단정하지 않고 개인정보처리방침에 수집 항목을 명시한다.

> **갱신 (2026-07-29)** — 입력 항목에 **성별**이 추가됐다. 아래 "성별을 온보딩에서
> 받는다" 참조. 이메일·전화번호·실명을 받지 않는다는 결정 자체는 그대로다.
