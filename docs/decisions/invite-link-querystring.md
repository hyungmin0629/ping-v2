# 초대 링크는 동적 라우트 대신 쿼리스트링으로 만든다

**결정** — 초대 링크 주소를 `/add/<코드>` 가 아니라 **`/add?code=<코드>`** 로 한다.

**이유** — 이 개발 환경(Windows + Next 16)에서는 **동적 라우트가 개발 서버에서 열리지
않는다.** 내용을 지운 최소한의 `/probe/[x]` 로도 재현된다 — HTTP 500,
`Jest worker encountered 2 child process exceptions`. 정적 라우트는 멀쩡하고
`next build` 도 통과하므로 프로덕션에서는 동작할 가능성이 높지만,
**로컬에서 확인할 수 없는 구조를 서비스 경로에 두지 않는다.**
확인할 수 없으면 고칠 수도 없다.

**대안** — 동적 라우트를 쓰고 프로덕션에서만 시험. 기각. 배포해야만 확인되는 코드는
고치는 속도가 몇 배로 느려지고, 실패가 이용자에게 먼저 보인다.

**영향**
- 주소가 조금 길어진다. 카톡으로 주고받는 데는 차이가 없다.
- 앱 전체에 동적 라우트가 하나도 없다. 모든 라우트가 정적으로 빌드된다.
- `useSearchParams` 는 Suspense 경계가 필요해 페이지를 감쌌다.
- 원인이 환경에 있으므로, 개발 환경이 바뀌면 다시 볼 수 있다. 그때도 이득은
  주소 모양뿐이다.
