# 합성 데이터와 실유저 데이터를 분리

**결정** — 운영 DB(Supabase)에는 실유저만. 합성 데이터는 별도 스키마/프로젝트에 두고,
BigQuery 적재 시 `is_synthetic` 플래그로 구분한다. 합성 규모는 유저 5,000명 / 3개월치.

**이유** — 섞으면 실유저가 존재하지 않는 가짜 유저를 투표 후보로 보게 된다. 분석도 오염된다.
반대로 합성 데이터가 아예 없으면 지인 30명이 만드는 수천 행으로는 Airflow가 할 일이 없어
증분 적재·스케줄링·재시도를 연습할 수 없다.

**대안** — 유저 5만 명 / 6개월치. 규모를 줄인 이유는 생성 시간과 무료 티어 여유 때문이고,
5,000명 / 3개월이면 파이프라인 검증에 충분하다.
