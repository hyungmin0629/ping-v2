# DDL 주석은 마이그레이션 뒤에 낡는다

**발견** — `db/ddl/` 만 읽고 힌트 요금을 **200 → 300 → 500 → 1000 누진**이라고
말했다. 그 요금제는 **W14(마이그레이션 006)가 반년 전에 없앤 것**이고, 현행은
기본 5종 각 20하트 + 이름 공개 100하트다. 죽은 값을 근거로 지표를 설계할 뻔했다.

## 왜 안 보이나

`db/apply.py` 는 **DDL + 마이그레이션 전부**를 순서대로 적용한다. 그러니
`db/ddl/*.sql` 은 현재 스키마가 아니라 **출발 상태**다. 진실은 파일 하나가
아니라 **파일들의 순서**에 있다.

그런데 사람도 에이전트도 `db/ddl/` 을 "스키마 정의서"로 읽는다. CLAUDE.md 가
"스키마 구조는 **DDL이 진실**"이라고 적어둔 것도 그 오해를 거든다 — 맞는
말이지만 **DDL 폴더 하나가 아니라 DDL+마이그레이션이 진실**이라는 뜻이다.

제일 고약한 지점: 006 은 자기가 바꾼 사실을 `COMMENT ON COLUMN` 으로
**DB 안에는 정정해 넣었다.** 그래서 살아 있는 DB 를 보면 맞는 설명이 나온다.
정정이 도달하지 않은 곳은 **사람이 실제로 읽는 파일**뿐이었다.

**결정** — 마이그레이션이 갈아치운 DDL 블록에는 **그 자리에 경고를 남긴다.**
"무엇이 바뀌었고 어느 마이그레이션이 바꿨는지"를 컬럼 단위로 적는다.

## 무엇을 고쳤나 (2026-08-13)

| 파일 | 낡아 있던 것 |
|---|---|
| `30_question_vote.sql` `hint_purchase` | 누진 요금 · `step` 의 뜻(단계→순서) · `heart_cost > 0`(→`>= 0`) · `uq_hint_step`(→`uq_hint_kind`) · 없는 것으로 보이던 `char_index`·`ad_impression_id` |
| `30_question_vote.sql` `vote_received` | 008 의 답장 · 004 의 `updated_at` 이 안 보였다. 007 이 옮긴 `hint_char_index` 를 여기서 찾게 돼 있었다 |
| `30_question_vote.sql` `vote_item` | 003 의 `padded_count` 가 안 보였다 |
| `60_board.sql` **전체** | "**익명** 게시판" · "v1 에서 **개통하지 않는다**" — W9 가 닉네임 게시판으로 **이미 열었다.** `anonymous_seq NOT NULL` 과 `uq_comment_anon` 은 005 가 걷어냈다(안 걷으면 한 사람이 한 글에 댓글을 두 번 못 단다) |
| `10_reference_user.sql` `school` | "`neis_school_code` 는 API 연동 키" — **그것만으론 못 부른다.** 001 의 `neis_office_code` 와 한 쌍이어야 한다. 002 의 `info_school_id` 도 없었다 |

**주석만 고쳤다. SQL 문장은 한 줄도 건드리지 않았다** — 그 문장들은 재생성의
출발점이고, 마이그레이션이 그 위에서 도는 것을 전제한다. `CHECK` 를 현행으로
"고치면" 006 이 이미 있는 제약을 다시 만들다 깨진다 — `db/replay_check.py` 가
잡으라고 있는 바로 그 함정이다.

## 왜 이 방식인가

**대안 1 — DDL 을 현행으로 접어 넣고 마이그레이션을 지운다.** 기각. 옛 DB 를
새 DDL 로 따라잡을 방법이 없어지고, "왜 그렇게 바뀌었나"가 통째로 사라진다.
마이그레이션 헤더는 이 저장소에서 **가장 잘 쓰인 결정 기록**이다.

**대안 2 — `doc_lint` 가 자동으로 잡게 한다.** 지금은 못 한다. lint 는
문서 주장을 **살아 있는 DB** 와 대조하는데, 여기서 어긋난 것은 DB 가 아니라
**같은 저장소 안 두 파일**이다. 붙일 수 있는 검사는 있다 — 예를 들어
"마이그레이션이 `ALTER TABLE X` 를 했는데 `db/ddl/` 의 X 블록에 그 번호가
안 적혀 있으면 알린다". 값싸고 기계적이다. **아직 만들지 않았다.**

**영향**

- `db/ddl/` 을 인용하기 전에 **그 표를 건드린 마이그레이션이 있는지 먼저 본다.**
  `grep -l "ALTER TABLE <표>" db/migrations/*.sql`
- 새 마이그레이션을 쓸 때, 갈아치운 DDL 블록에 경고를 함께 남긴다.
  마이그레이션 헤더에만 적으면 **읽히지 않는다.**
- 이어지는 결정: [[integrity-checks-aged]] 와 같은 병이다 — 검사도 주석도
  **쓰인 시점의 세계를 알고 있고**, 기능이 늘 때마다 그 세계가 바뀐다.
