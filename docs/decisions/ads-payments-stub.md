# MVP에서 광고와 결제를 스텁으로 처리

**결정** — 셔플에 필요한 광고는 3초 대기 스텁으로, 하트 충전은 아예 제외한다.

**이유** — AdMob·인앱결제는 계정 개설과 심사가 필요해 MVP 일정에 맞지 않는다.
스키마(`ad_impression`, `heart_purchase`)는 이미 준비돼 있으므로 나중에
실제 SDK를 붙일 때 구조를 바꿀 필요가 없다.

**영향** — MVP에서 하트는 가입 지급과 투표 적립으로만 늘어난다.
힌트를 많이 사면 잔액이 마르는데, 이는 오히려 하트 경제의 균형을 관찰할 기회다.

## 이어지는 결정
- [[shuffle-once-constraint|셔플은 DB 제약으로 1회를 강제한다]]
  — 셔플에 광고를 붙였는데 MVP 의 그 광고가 스텁이다
- [[topup-stub-daily-limit|하트 충전은 결제 없는 스텁 — 대신 하루 한 번]]
  — MVP 의 스텁 둘 — 결제와 광고
