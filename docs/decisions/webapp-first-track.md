# 웹앱을 최우선 트랙으로 재편

**결정** — 파이프라인(P3~P7)을 뒤로 미루고 웹앱 MVP를 먼저 만든다.

**이유** — v1 설계서에는 **접속해서 볼 수 있는 화면이 진행 순서에 아예 없었다.**
9단계를 다 끝내도 나오는 것은 BigQuery 테이블과 대시보드뿐이었다. 대화에서는
3단계(파이프라인 → 웹앱 → 배포)로 제안해놓고 문서에는 파이프라인만 담은 누락이다.

두 달간 눈에 보이는 결과가 없으면 프로젝트가 추상적으로만 느껴져 흐지부지되기 쉽다.
또 **웹앱을 만들어봐야 스키마의 진짜 문제가 드러난다** — 실제로 "친구를 어떻게 추가하지?"라는
질문에서 초대 코드 개념이 스키마에 없다는 게 바로 드러났다.

**영향** — P0~P2가 이미 끝나 786만 행이 DB에 있으므로 여기서 멈춰도 손실이 없다.
파이프라인은 웹앱 배포 후 재개하며, 그때는 실유저 데이터가 함께 흐른다.
