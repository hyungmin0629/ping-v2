# 학교를 순차로 열고, 학급 수를 정원에서 유도한다

**결정** — [Q5] 의 "순차 확산"을 실제로 구현한다. 학교마다 **계층 · 정원 ·
개교일**을 정하고, **가입일 순서로 그 시점에 열려 있는 학교 중에서** 고른다.
학급 수는 고정 범위가 아니라 **정원에서 유도**한다.

**이유** — 설정에 `schools.tiers` 와 `schools.adoption` 이 있었지만
`load_config()` 의 복사 목록에서 빠져 **통째로 사라져 있었다.** 그래서
50개 학교가 전부 첫날 열렸고, 정원이 기본값(40~250)으로 잡혀 20,000명 중
2,535명이 정원을 넘겨 배정됐다. **오류는 나지 않았다.**

## 순서가 핵심이다 — 가입일이 먼저다

1. 학교마다 계층(core/mid/tail)·정원·개교일을 정한다
2. **가입일을 전부 먼저 뽑아 정렬한다** (성장 곡선이 정한 값)
3. 가입일 순서로, 그 시점에 열려 있고 정원이 남은 학교를 고른다
4. 가중치는 `남은 정원 × 로지스틱 램프` — 개교 직후는 낮게 잡아 학교 안
   확산이 S자를 그린다

**반대로 하면 두 분포가 서로를 망친다.** 학교를 먼저 고르고 가입일을
나중에 뽑으면 성장 곡선이 개교일에 눌린다.

## ⚠️ 학급 수를 정원에서 유도해야 하는 이유

고정 범위(9~18반)를 쓰면 **정원 975명인 core 학교의 한 반이 77명**이 된다.
인기도는 학급 안 순위로 정해지므로(`popularity.scope: class`) 반이 커지면
순위 스프레드가 커져 **쏠림이 커진다** — 실제로 상위 10% 점유가 44%에서
51%로 뛰었다.

`n_classes = 정원 / 학급당 평균` 으로 바꿔 학급당 중앙값 15명(목표 14~22)이 됐다.

**대안** — 학교 정원을 줄여 학급 수와 맞추는 안을 기각했다. 그러면 50개
학교로 20,000명을 담을 수 없다.

**영향**

- core 10곳이 9월에 1,000명 규모로, tail 25곳이 6~7월에 13~62명으로 들어온다.
  **"이 학교는 언제 들어왔나"가 분석 축이 된다.**
- 정원 초과 배정이 **0명**이 됐다.
- ⚠️ **연쇄 효과** — 학급이 636 → 1,208개가 되면서 **같은 반 친구 비율이
  25%(설정) → 14.1%** 로 떨어졌고, CLASS 스코프 비중도 35% → 30.6% 가 됐다.
  같은 반 관계를 다루는 분석의 표본이 설정보다 적다.
- 이 결함의 성격은 [[growth-curve-two-channels]] 와 같다 —
  **설정에 값이 있어도 코드가 안 읽으면 없는 것이다.**
