# P5~P7 시작하기

EDA(AARRR)까지 끝난 상태에서 **다음 네 가지를 어떤 순서로, 어떤 명령으로**
시작하는지 적는다. 각 단계마다 "무엇을 하는가 · 명령 · 끝났다의 기준"이 있다.

> 명령은 전부 `.venv` 로 돈다. 활성화해 뒀다면 `python`, 아니면
> `.venv\Scripts\python.exe` (Git Bash 는 `./.venv/Scripts/python.exe`).

---

## 왜 이 순서인가

층이 넷이고, **앞이 틀리면 뒤는 전부 틀린다.** 그런데 뒤로 갈수록
틀린 것이 안 보인다 — 대시보드는 숫자가 틀려도 예쁘게 나온다.

| 층 | 무엇 | 형태 | 누가 읽나 |
|---|---|---|---|
| **raw** | 원본 그대로. 제약도 정리도 없다 | 테이블(파티션) | 파이프라인만 |
| **stg** | 실수를 구조적으로 막은 층 | **뷰** (저장 0) | mart 와 분석자 |
| **mart** | 지표를 미리 계산해 둔 표 | **테이블** (작다) | 대시보드 |
| **대시보드** | 그림 | 루커 스튜디오 | 사람 |

그래서 **P5(raw 를 믿을 수 있나) → stg(정리) → mart(지표) → 대시보드** 다.

## 0. 시작 전 — 적재부터 다시 돌린다

⚠️ **2026-08-18 확인: 실유저 데이터가 12일치 안 올라와 있다.**
BigQuery 의 워터마크가 `2026-08-06` 에 멈춰 있고, Supabase 에는 `2026-08-13`
까지의 투표가 있다(`vote_item` 최신 시각 기준). P5 를 그 상태로 돌리면
"깨끗한 옛날 데이터"를 검증하게 된다.

```
python pipeline/extract_load.py --source supabase
```

끝나면 행 수를 대조한다. **증분은 조용히 틀린다** — 이 확인이 없으면 모른다.

```
python pipeline/verify_load.py --source supabase
```

## P5 · 품질검증 — `qa/quality_check.py`

### 무엇을 하는가

`verify_load.py` 와 헷갈리기 쉬운데 **묻는 것이 다르다.**

| | 묻는 것 |
|---|---|
| `verify_load.py` | 원천의 행이 **다 왔나** (개수 대조) |
| `quality_check.py` | 온 행을 **믿어도 되나** (내용 검증) |

raw 층은 일부러 제약이 없다. 적재기가 모든 컬럼을 NULLABLE 로 만들고 외래키도
걸지 않는다 — 원천 스키마가 느슨해질 때 적재가 통째로 죽지 않게 하려는 선택이다.
**그래서 검증이 적재 시점이 아니라 여기에 있다.**

검사는 손으로 적지 않는다. `docs/erd.json`(살아 있는 스키마)을 읽어 표마다
자동으로 만든다 — 표가 늘면 검사도 는다. **지금 430개.**

| 구분 | 보는 것 | 개수 |
|---|---|---|
| 유일성 | `(_source, id)` 가 중복되지 않는가 | 40 |
| 필수값 | 원천이 NOT NULL 인 컬럼에 NULL 이 없는가 | 276 |
| 참조 | 부모 없는 자식 행이 없는가 (**같은 `_source` 안에서만**) | 75 |
| 시각 | 미래 시각 · 뒤집힌 순서(`voted_at < served_at` 등) | 39 |
| 적재 상태 | 워터마크가 언제 것인가 (정보) | — |

### 명령

먼저 **얼마나 스캔하는지만** 본다. 쿼리 무료 한도가 월 1 TiB 뿐이라
비용을 모르고 켜지 않는다.

```
python qa/quality_check.py --source supabase --estimate
```

숫자를 보고 괜찮으면 실제로 돌린다.

```
python qa/quality_check.py --source supabase
```

합성 데이터도 같은 방법으로 본다 (`--source local`).

### 끝났다의 기준

- 네 구분 전부 `✅`, 위반 0
- 리포트가 `qa/reports/quality-<날짜>-<원천>.md` 로 남고, 그것을 커밋했다

**실측 (2026-08-18)** — 두 원천 다 **430/430 통과**. 한 번에 11.7 GiB 를
스캔한다(월 무료 한도의 1.1%). 매일 돌려도 한 달 34% 다.

### 언제 다시 도나

- 적재를 돌린 뒤
- **스키마를 바꾼 뒤** — 컬럼을 추가하면 `updated_at` 이 안 움직여 증분이
  못 잡는다. 그 컬럼이 통째로 NULL 로 남고, "필수값" 검사가 그것을 잡는다

## P6-1 · 스테이징 — `bigquery/build.py --layer stg`

### 무엇을 하는가

**raw 를 그대로 쓰지 못하게 만드는 층**이다. 분석에서 실제로 걸렸던 실수 넷을
사람의 기억이 아니라 **컬럼으로** 막는다.

| 막는 실수 | 어떻게 |
|---|---|
| 두 원천의 id 가 겹친다 (`app_user` 16개) | `user_key = 'local-123'` 같은 **대리키**. `USING(id)` 를 못 쓰게 된다 |
| 지운 행의 유령 | `_deleted_at IS NULL` 을 뷰 안에서 한 번만 건다 |
| 시간대가 9시간 밀린다 | `signup_date` 처럼 **KST 날짜를 미리 계산**해 싣는다 |
| 광고 무료 힌트가 '구매'로 세어진다 | `is_paid_hint` · `is_ad_hint` 로 갈라 둔다 |
| 스텁 충전이 매출로 세어진다 | `is_stub` · `is_revenue` 로 갈라 둔다 |
| 제재 유저를 유저 단위로 빼면 과거까지 사라진다 | `valid_until` **시각**을 싣는다 |

### 왜 테이블이 아니라 뷰인가

raw 가 이미 8.74 GiB 라 **무료 저장 한도 10 GiB 의 여유가 1 GiB 남짓**이다.
stg 를 테이블로 구우면 그 여유가 사라진다. 뷰는 저장이 0이고, 읽는 쪽이
mart 와 분석자뿐이라 재조회 비용도 작다.

거꾸로 **mart 는 테이블이어야 한다.** 대시보드는 화면을 그릴 때마다 쿼리를
날리는데, 뷰로 두면 그때마다 1억 2천만 행을 다시 읽는다.

### 명령

문법과 스캔량만 먼저 본다.

```
python bigquery/build.py --layer stg --dry-run
```

괜찮으면 만든다. (`stg` 데이터셋이 없으면 자동으로 만든다.)

```
python bigquery/build.py --layer stg
```

### 지금 있는 것 (2026-08-18 생성 완료)

| 뷰 | 한 행이 뜻하는 것 |
|---|---|
| `stg.stg_user` | 유저 한 명 (+ 소속 · 탈퇴 · 제재 · `valid_until`) |
| `stg.stg_user_session` | 접속 세션 한 건 (+ 체류시간 · 중복 표시) |
| `stg.stg_vote_item` | 출제된 질문 한 건 (+ 질문 마스터 · 응답 소요) |
| `stg.stg_hint_purchase` | 힌트를 연 기록 한 건 (+ 유료/광고 구분) |
| `stg.stg_heart_transaction` | 하트 원장 한 줄 (+ 적립/소비 분리) |
| `stg.stg_heart_purchase` | 충전 시도 한 건 (+ 스텁/매출 구분) |

**SQL 은 `bigquery/staging/*.sql` 이 진실이다.** 파일 이름의 번호가 실행 순서다.

### 끝났다의 기준

- `--dry-run` 없이 6개 파일이 전부 `생성` 으로 끝났다
- BigQuery 콘솔에서 `stg.stg_user` 를 `LIMIT 10` 으로 열어 대리키가 보인다

## P6-2 · 마트 — **여기는 결정이 먼저다**

⚠️ **마트는 "무엇을 볼 것인가"가 정해진 뒤에 만든다.** 표를 먼저 만들면
지표를 표에 맞추게 된다.

지표는 이미 `notebooks/dashboard.ipynb` 에 **12개**가 들어 있다. 마트는
그 12개를 **매번 다시 쓰지 않아도 되게** 굽는 일이다.

| # | 지표 (dashboard.ipynb) | 그레인 제안 |
|---|---|---|
| 1 | 총매출 · 월별 매출 | 일자 × 원천 |
| 2 | 월별 신규 가입자 | 일자 × 원천 |
| 3 | 일별 접속자 수(DAU) | 일자 × 원천 |
| 4 | 일별 접속자 중 투표 참여율 | 일자 × 원천 |
| 5 | 월별 하트 적립 · 충전 · 소비 | 일자 × 원천 |
| 6 | 무료 지급 vs 유료 충전 vs 소비 | 일자 × 원천 |
| 7 | 투표 수신 미경험률 | 유저 |
| 8 | 미경험자의 친구 5명 해금 여부 | 유저 |
| 9 | 가입 후 7일 내 신규 친구 수 | 유저 |
| 10 | 힌트 전환 퍼널 (열람 → 힌트 → 이름 공개) | **퍼널 단계** |
| 11 | 투표 세트 10문항 완료율 | **퍼널 단계** |
| 12 | 신고 처리 상태 · 미해결 적체 | 상태 × 일자 |

⚠️ **이 표는 제안이지 결정이 아니다.** 그레인이 정해지면 그때
`docs/decisions/` 에 결정 노드를 만든다.

읽는 법 — **그레인이 세 갈래**로 갈린다. 일자 시계열(1~6) · 유저 한 명(7~9) ·
퍼널 단계(10~11). 하나의 표로 12개를 다 담을 수 없다는 뜻이고,
**표가 최소 3개**라는 뜻이다.

### 지금 저장소에 있는 것

`bigquery/mart/` 에 **초안 3개**가 있다. 파일은 있지만 **BigQuery 에는 아직
만들지 않았다**(문법 확인만 했다 — 3.7 GiB 스캔).

| 초안 | 그레인 | 위 지표 중 |
|---|---|---|
| `10_mart_user.sql` | 유저 한 명 | 7 · 8 · 9 의 재료 |
| `20_mart_daily_activity.sql` | 일자(KST) × 원천 | 2 · 3 · 4 |
| `30_mart_revenue_daily.sql` | 일자(KST) × 원천 | 1 · 5 · 6 |

**빠진 것은 퍼널(10 · 11)과 신고(12)** 다. 그레인을 확정한 뒤 채운다.

### 마트 SQL 을 쓸 때 지키는 것

- **raw 를 직접 읽지 않는다.** 항상 `stg` 를 읽는다. 표준 필터가 거기 있다
- **집계 시점에 걸러 담는다.** 마트에 들어온 행은 이미 걸러진 것으로 본다
  (운영자 제외 · 탈퇴/영구정지 이후 활동 제외 · 중복 세션 제외)
- **차원 표(유저)는 걸러 담지 않는다.** 탈퇴자를 지우면 이탈률의 분자가 사라진다.
  플래그로 싣고 거르는 것은 보는 쪽이 고른다
- 날짜 컬럼으로 `PARTITION BY`, 원천으로 `CLUSTER BY`

만들 때 명령은 stg 와 같다.

```
python bigquery/build.py --layer mart --dry-run
python bigquery/build.py --layer mart
```

## P7 · 루커 스튜디오

코드가 필요 없는 단계다. **파이썬은 여기서 끝난다.**

### 순서

1. https://lookerstudio.google.com 에 **BigQuery 와 같은 구글 계정**으로 들어간다
2. 만들기 → 데이터 원본 → **BigQuery** 커넥터
3. 프로젝트 `ping-v2-503916` → 데이터셋 **`mart`** → 표를 고른다
4. 보고서 만들기 → 차트를 얹는다

### ⚠️ `raw` 를 직접 연결하지 않는다

루커 스튜디오는 **화면을 새로 그릴 때마다 쿼리를 날린다.** 필터를 한 번 바꾸면
한 번 더 날아간다. `raw` 를 연결하면 그때마다 1억 2천만 행을 읽는다 —
월 1 TiB 무료 한도는 이렇게 사라진다. **연결은 `mart` 만.**

### 그 외 주의

- **원천 필터를 반드시 건다.** 실유저는 20~50명이라 합성과 섞이면 비율이 무의미해진다.
  보고서 수준 필터로 `source = 'local'` (또는 `'supabase'`)을 고정한다
- 데이터 원본 설정에서 **캐시를 켜 둔다**(기본 켜짐). 12시간 캐시면 같은 화면을
  여러 번 봐도 쿼리는 한 번이다
- 공유는 **보고서 단위**다. 팀원은 이미 BigQuery 관리자로 붙어 있다
  ([[ops-bigquery-team-access]])
- 날짜 필드는 마트에 이미 KST 로 들어 있다. 루커에서 시간대를 또 바꾸지 않는다

## 자주 나는 오류

| 메시지 | 뜻 | 할 일 |
|---|---|---|
| `Dataset ... was not found` | `stg`/`mart` 데이터셋이 없다 | `build.py` 를 한 번 돌리면 만든다 |
| `Not found: Table ... stg_user` | stg 를 안 만들고 mart 를 돌렸다 | `--layer stg` 부터 |
| `403 ... quota exceeded` | 무료 한도(쿼리 1 TiB/월) | `--estimate` · `--dry-run` 으로 먼저 재는 습관 |
| 품질검사에서 "참조" 위반 | 부모 없는 자식 행 | 적재 순서 문제일 때가 많다. `--full-refresh` 로 그 표만 다시 |
| 품질검사에서 "필수값" 위반 | 컬럼을 추가했는데 증분이 못 잡았다 | 그 표를 `--full-refresh` |
