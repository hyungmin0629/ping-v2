# 작업 이력

위키에 **무엇을 언제 했나.** 덧붙이기만 하고 고치지 않는다.

git log 와 다르다 — git 은 파일이 어떻게 바뀌었는지를 남기고, 여기는
**원본을 반영했는지 · 색인을 다시 세웠는지 · 검사를 돌렸는지**를 남긴다.
회의록을 넣고 반영을 잊어버리는 것이 제일 흔한 사고라 그걸 잡는 것이 목적이다.

형식: `## [YYYY-MM-DD] 연산 | 한 줄`

연산은 셋이다 — `ingest`(원본을 읽어 위키에 반영) · `query`(물음에 답하고
답을 남김) · `lint`(어긋난 곳을 찾아 고침). 자세한 절차는 [[CLAUDE|CLAUDE.md]].

## [2026-08-05] query | 투표 활동 분포를 자세히 파다가 결함 1건을 찾음

"상위 10%가 90%를 던진다는데 정확한 분포를 보고 싶다"는 물음.
십분위 · 분위수 · 히스토그램 · 로렌츠 · 상위 20명으로 갈라 봤다.

**분포 자체** — 중앙값 29표 · 평균 1,224표(42배 차이) · 최대 545,707표.
상위 0.1%(17명)가 15.85%, 상위 1%(167명)가 48.54%. 지니 0.9364.
히스토그램이 **이중 봉우리**다 — 사람은 10~49표 구간(6,789명)에 몰려 있는데
투표는 10,000표 이상 구간(402명)이 66.52%를 가져간다.

**집중의 원인은 친구가 아니라 기간이었다.** 십분위별로 갈라 보니
친구 수는 1분위 44.8 · 8분위 39.8 로 **1.1배**인데 투표 수는 **1,557배**다.
같이 움직이는 것은 활동 기간(91.9일 ↔ 1.3일)과 세션 수(1,053 ↔ 1).

**⚠️ 그러다 결함을 찾았다** — 하루 투표 세션 수에 **상한이 없다.**
하루 최다 2,243세션, 투표에 쓴 시간 최대 **406.8시간/일**,
24시간 초과가 1,251 유저-일(67명). 1위 유저는 하루 554세션 · 99.2시간.
2위는 314일 동안 458,887번 던지고 **한 번도 지목받지 못했다.**
16위는 **친구 8명으로 98,862번** 던졌다.

정합성 17종·이상치 9종이 이걸 안 묻는다 — "하루에 몇 번까지가 사람인가"는
스키마 제약으로 표현되지 않는다.

**확정 결정은 유지하되 성격을 갈랐다** — 앞의 5건은 "이 축으로는 답을 못 한다"(경계),
이건 "답이 틀리게 나온다"(결함). 영향이 꼬리 0.5%에 갇혀 있어 두 규칙
(상위 1% 안 봄 · 집중 지표 절대값 인용 안 함)으로 막고, **v5 1순위**로 올렸다.

리포트에 **7-2장**이 통째로 붙었다. 23쪽 → **27쪽**.
