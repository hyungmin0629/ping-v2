# raw — 원본 자료 (1계층)

**여기 있는 파일은 고치지 않는다.** 읽기만 한다.

이 프로젝트의 문서 체계는 세 층이다([[CLAUDE|CLAUDE.md]] 의 *위키 구조* 참조).
`raw/` 는 그중 첫 층이고, **바깥에서 들어온 사실**을 그대로 보관한다.

| 층 | 무엇 | 누가 쓰나 |
|---|---|---|
| **1. `raw/`** | 원본. 회의록·분석 리포트·외부 스펙 | **사람.** 에이전트는 읽기만 |
| 2. `docs/` | 원본과 코드에서 **뽑아 만든** 문서 | 에이전트 |
| 3. `CLAUDE.md` | 그 일을 어떻게 하는지 | 사람 + 에이전트 |

## 왜 고치지 않나

원본을 고치면 **무엇이 사실이고 무엇이 우리 해석인지 구분할 수 없게 된다.**

회의에서 "학교 20곳으로 하자"고 했는데 나중에 30곳으로 바꿨다면, 회의록은
**20곳인 채로 둔다.** 바뀐 것은 `docs/decisions/` 에 새 결정으로 적는다.
그래야 "언제 왜 마음이 바뀌었나"가 남는다.

오타 수정 정도는 괜찮다. 내용을 바꾸는 것이 안 된다.

## 무엇을 넣나

| 폴더 | 넣는 것 |
|---|---|
| `meetings/` | 회의록. 파일명 `YYYY-MM-DD-주제.md` |
| `legacy-analysis/` | 구 서비스 DB 분석 리포트 (2026-07-28) |
| `external/` | NEIS API 스펙, 외부 문서, 참고 자료 |

**넣지 않는 것** — 코드에서 알 수 있는 것. 스키마 정의, 명령어, 실행 결과.
그건 DDL과 스크립트가 진실이고, 문서로 옮겨 적으면 두 번째 진실이 생긴다.

## legacy-analysis 가 여기 있는 이유

ping-v2 의 거의 모든 문서가 이 리포트의 숫자를 인용한다 —
탈퇴 70,764건, 잔액 20억, 가입자 67.7만, FK 39개 중 17개 선언.
그런데 **원본은 저장소 밖(`final/data/reports/`)에 있었고 git 으로 추적되지도
않았다.** 인용만 있고 출처가 없는 상태였다.

들여왔으므로 이제 [[00_key_findings]] 로 직접 갈 수 있다.

## 회의록을 넣은 뒤에 할 일

원본을 넣는 것으로 끝이 아니다. 에이전트에게 **읽고 반영해달라고** 해야 한다
(`ingest`). 그러면 결정은 `docs/decisions/` 로, 할 일은 계획 문서로 옮겨지고,
`docs/log.md` 에 기록이 남는다. 절차는 [[CLAUDE|CLAUDE.md]] 에 있다.
