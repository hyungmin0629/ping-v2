# 신고 & 제재 시스템 분석

조사 시점: 2026-07-28 / DB: `mysql` 컨테이너(포트 3307) → `final` 스키마
대상: `accounts_user`(`report_count`, `ban_status`), `polls_questionreport`, `accounts_timelinereport`, `accounts_blockrecord`

## 1. 제재 상태(`ban_status`) 분포

| 상태 | 인원 | 비중 | 평균 피신고횟수(`report_count`) |
|---|---|---|---|
| N (정상) | 668,432 | 98.7% | 0.04 |
| W (탈퇴) | 7,855 | 1.16% | 0.03 |
| NB (제재①) | 608 | 0.09% | 0.01 |
| RB (제재②) | 190 | 0.03% | 0.24 |

NB/RB 두 제재 카테고리 중 **RB만 피신고횟수 평균이 뚜렷하게 높다(0.24, 정상유저의 6배)** — RB가 "신고 누적에 따른 제재", NB가 "신고와 무관한 제재(운영자 직권 등)"일 가능성이 높아 보이나, 정확한 정의는 코드/기획 문서 확인 필요.

## 2. 핵심 발견: 신고를 아무리 많이 받아도 실제 제재로 거의 이어지지 않는다

`report_count`(피신고 누적 횟수) 10회 이상인 유저 116명의 실제 상태:

| ban_status | 인원 |
|---|---|
| N (정상, 그대로 활동 중) | 113 |
| W (탈퇴) | 3 |
| NB/RB (제재) | **0** |

가장 많이 신고받은 유저(`id=831962`, **253회 피신고**)조차 `ban_status='N'`으로 정상 상태이며 포인트 2,248점도 그대로 보유 중이다. 상위 10명(피신고 20회 이상) 전원이 제재 없이 정상 상태다.

→ **신고 시스템(`report_count` 누적)과 실제 제재(`ban_status`) 사이에 자동/실질적 연결고리가 없어 보인다.** 신고가 쌓여도 별도의 수동 검토 없이는 제재로 이어지지 않는 구조로 추정됨 — 안전/신뢰 관점에서 재점검이 필요한 지점.

## 3. 신고 시스템 두 종류의 온도차

- `polls_questionreport`(질문 신고, 51,424건): [table_notes.md](01_table_notes.md) 기준 서비스 기간 내내 꾸준히 발생 — 메인 신고 채널. 상위 신고자 1명이 **865건**을 신고(2위 271건과 큰 격차) — 특정 유저의 이상 사용 패턴이거나 관리자/모니터링 계정일 가능성.
- `accounts_timelinereport`(유저 신고, 208건): 2023-05-06~06-02 한 달만 존재하고 이후 없음(기능 축소 추정). 사유 분포: 허위 사실 언급 38.5%, 친구 비하/조롱 30.8%, 선정적·폭력적 내용 18.8%, 사칭 7.2%, 광고 4.8%. `polls_questionreport`보다 훨씬 구체적인 사유 체계를 갖고 있었는데 왜 한 달 만에 중단됐는지는 불명확.

## 4. 차단(`accounts_blockrecord`)은 "신고"보다는 "관계 정리"에 가깝다

| 차단 사유 | 건수 | 비중 |
|---|---|---|
| 모르는 사람임 | 9,640 | 49.5% |
| 친구 사이가 어색해짐 | 5,805 | 29.8% |
| 사칭 계정 | 2,022 | 10.4% |
| 나랑 관련 없는 질문을 자꾸 보냄 | 1,083 | 5.6% |
| 너무 많은 양의 질문을 보냄 | 919 | 4.7% |

**차단 사유의 79.3%("모르는 사람"+"어색해짐")가 악성 행위가 아니라 단순 관계 정리**다. 실제로 차단당한 적 있는 유저(16,240명)와 없는 유저를 비교하면:

| 구분 | 평균 피신고횟수 | 제재 비율 |
|---|---|---|
| 차단당한 적 있음 | 0.11 | 0.209% |
| 차단당한 적 없음 | 0.04 | 0.116% |

차단당한 유저가 피신고횟수·제재비율 모두 약 2배 높긴 하지만 절대값 자체가 작아서, "차단 = 문제유저"라는 등식은 성립하지 않는다.
