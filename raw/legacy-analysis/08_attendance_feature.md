# 출석 기능 분석

조사 시점: 2026-07-28 / DB: `mysql` 컨테이너(포트 3307) → `final` 스키마
대상: `accounts_attendance`(유저당 1행, `attendance_date_list`에 출석일 JSON 배열). [table_notes.md](01_table_notes.md)에서 "1.6.0 업데이트로 추가된 기능이라 진짜 미출석과 업데이트 이전 가입자가 섞여있다"고 이미 언급한 한계가 그대로 적용됨.

## 1. 유저별 참여 강도 — 대부분 "찍먹"

| 출석 횟수 구간 | 인원 | 비중 |
|---|---|---|
| row 자체 없음(기능 출시 전 가입 등) | 327,448 | 48.4% |
| 0회(row는 있지만 빈 배열) | 20,945 | 3.1% |
| 1~5회 | 201,533 | 29.8% |
| 6~20회 | 108,861 | 16.1% |
| 21~50회 | 16,187 | 2.4% |
| 51회 이상 | 2,111 | 0.3% |

row가 있는 유저(349,637명, 전체의 51.6%) 중에서도 **57.7%(201,533명)가 1~5회만 체크하고 그친다.** 51회 이상 꾸준히 체크한 "습관화" 유저는 전체 가입자의 0.3%뿐.

## 2. 요일별 출석 패턴

| 요일 | 출석 건수 |
|---|---|
| 월요일 | 382,739 |
| 화요일 | 371,520 |
| 일요일 | 344,663 |
| 토요일 | 325,030 |
| 수요일 | 280,063 |
| 목요일 | 266,176 |
| 금요일 | 252,136 |

**월요일이 가장 높고 금요일이 가장 낮다** — 주중/주말 뚜렷한 이분법(예: 평일 몰림 또는 주말 몰림)이 아니라, 월~화에 높았다가 주 중반~금요일로 갈수록 줄어들고 주말(특히 일요일)에 다시 살짝 회복하는 패턴. "한 주를 시작하며 다시 접속" 같은 습관과 맞아떨어짐.

## 3. 월별 트렌드 — 다른 기능과 다르게 6월이 정점

| 월 | 출석 건수 |
|---|---|
| 2023-05 | 611,238 |
| **2023-06** | **1,232,776** |
| 2023-07 | 200,306 |
| 2023-08 | 85,547 |
| 이후 지속 감소 | ~2,500 이하/월 (2024년 이후) |

[table_notes.md](01_table_notes.md)의 "핵심 발견 5"에서 대부분의 활동 테이블은 **2023-05**에 몰려있다고 했는데, 출석 기능만 예외적으로 **2023-06에 정점**(전체의 32.4%, 5월의 2배 이상)을 찍는다. 출석 기능이 5월 대량가입 이후 한 달 뒤(1.6.0 업데이트)에 추가됐다는 설명과 정확히 들어맞으며, 다른 기능들처럼 "런칭 즉시 스파이크 후 감소"가 아니라 "기능 출시 시점에 스파이크 후 감소"하는 패턴임을 보여준다.

## 후속으로 확인해볼 만한 것
- 출석과 실제 리텐션([retention_platform.md](02_retention_platform.md)) 간의 상관관계 — 출석 51회 이상 "습관화" 유저(2,111명)가 다른 활동 지표에서도 상위 파워유저와 겹치는지 확인
- row 자체가 없는 48.4%가 정말 "업데이트 이전 가입자"인지, 아니면 기능 자체를 발견 못 한 유저인지 가입일 분포로 교차 확인
