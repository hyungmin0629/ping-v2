# 투표 퍼널 분석 — 노출부터 답변 공개까지

조사 시점: 2026-07-28 / DB: `mysql` 컨테이너(포트 3307) → `final` 스키마
대상: `polls_questionpiece`(질문 노출) → `accounts_userquestionrecord`(투표 결과 레코드, `has_read`/`answer_status` 포함)
[table_notes.md](01_table_notes.md)에서 이미 "답변 공개 전환율이 낮다(9.2%)"고 언급했던 부분을 실제 단계별 퍼널로 쪼개서 어디서 이탈하는지 확인.

## 퍼널 전체 그림

| 단계 | 건수 | 이전 단계 대비 | 전체 대비 |
|---|---|---|---|
| 1. 질문 노출(`polls_questionpiece`) | 1,265,476 | - | 100% |
| 2. 투표 완료(`is_voted=1`) | 1,218,687 | 96.3% | 96.3% |
| 3. 투표 결과 레코드 생성(`accounts_userquestionrecord`) | 1,217,558 | 99.9% | 96.2% |
| 4. 대상자가 열람(`has_read=1`) | 675,931 | 55.5% | **53.4%** |
| 5. 답변 공개(`answer_status='A'`) | 111,761 | 16.5%(열람자 중) | **8.8%** |

**가장 큰 이탈은 "투표"가 아니라 "결과를 열어본 뒤에도 공개하지 않는 것"이다.** 투표 자체의 완료율은 96.3%로 매우 높아서 "투표하기 귀찮음"은 문제가 아님. 진짜 병목은 4→5단계: 알림을 열어본 사람(675,931명) 중에서도 **83.5%가 끝내 답변을 공개하지 않는다.**

## 열람 여부로 쪼갠 미답변 구조 (기존 table_notes.md 수치의 세부 분해)

| 상태 | 건수 | 비중 |
|---|---|---|
| 안 읽음(`has_read=0`) | 541,627 | 44.5% |
| 읽었지만 무응답(`has_read=1`, N) | 556,305 | 45.7% |
| 공개 답변(A) | 111,761 | 9.2% |
| 비공개 답변(P) | 7,865 | 0.6% |

기존에 "미답변 90.2%"로 뭉뚱그려졌던 수치가 사실은 거의 정확히 반반으로 나뉜다: **알림을 아예 안 열어본 사람(44.5%)과, 열어보고도 응답 안 한 사람(45.7%)이 비슷한 비중**이다. 즉 문제는 하나가 아니라 두 개다 — (a) 애초에 알림/앱 재진입을 안 하는 문제, (b) 재진입해서 열람까지 해놓고 굳이 응답할 유인이 없는 문제. 둘을 같은 원인으로 묶어서 해결하려 하면 안 됨.

## 결제 여부에 따른 차이 (하트 = 공개 유인이 아닌지 검증)

[payment_report.md](06_payment_report.md)에서 "하트 결제와 투표 활동이 분리되어 있다"고 봤는데, 혹시 "하트로 답변 공개를 구매"하는 구조가 있는 건 아닌지 확인:

| 구분 | 레코드 수 | 열람율 | 공개율 |
|---|---|---|---|
| 결제유저 | 148,656 | 57.4% | 10.3% |
| 비결제유저 | 1,068,902 | 55.2% | 9.0% |

결제유저가 열람율·공개율 모두 소폭(1~2%p) 높긴 하지만, 비결제유저도 9.0%나 되는 공개율을 보여 **"하트가 있어야 답변을 공개할 수 있다"는 식의 강한 페이월(paywall)은 아닌 것으로 보인다.** 결제유저가 전반적으로 좀 더 적극적인 유저층이라는 정도의 상관관계.

## 데이터 정합성 참고
- 2단계(투표 완료, 1,218,687건)와 3단계(레코드 생성, 1,217,558건) 사이에 1,129건(0.09%) 차이가 있음 — 투표했는데 레코드가 안 만들어진 극소수 케이스로, 무시할 만한 수준이나 완전한 1:1은 아님.
- `status` 필드 기준으로는 전체 레코드의 95.0%가 `C`(종료), 5.0%가 `I`(진행중 추정), 0.05%가 `B`(차단) — 위 열람/공개 비율은 상태와 무관하게 전체 기준.

## 후속으로 확인해볼 만한 것
- "열람했지만 공개 안 함"(45.7%)이 실제로 앱 UX 문제인지(공개 버튼이 안 보이거나 절차가 복잡함), 아니면 "누가 나를 뽑았는지 알려주면 어색해서" 같은 심리적 장벽인지 — 기획팀 인터뷰/코드 확인 필요
- "안 읽음"(44.5%) 그룹이 [retention_platform.md](02_retention_platform.md)의 조기 이탈(가입 1주 내 이탈 63.9%) 그룹과 얼마나 겹치는지 — 겹친다면 "안 읽음"은 리텐션 문제의 파생일 뿐, 별도 원인이 아닐 수 있음
